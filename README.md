# Prompt Engineering בפעולה - ממיר הוראות לפקודות CMD

Agent שמקבל הוראה בשפה טבעית (עברית או אנגלית) ומחזיר פקודת CMD אחת של Windows.
הקוד סביב ה-agent פשוט בכוונה. עיקר העבודה הוא הפרומפט, וכל גרסה שלו נמדדת מול אותה קבוצת תרחישים.

| הוראה | פקודה |
|---|---|
| מה כתובת ה-IP של המחשב שלי | `ipconfig` |
| אני רוצה למחוק את כל הקבצים עם סיומת .tmp בתיקייה downloads | `del downloads\*.tmp` |
| לסדר את רשימת הקבצים לפי גודל מהגדול לקטן | `dir /o-s` |
| איזה תהליכים רצים כרגע במערכת | `tasklist` |

## התקנה והרצה

```bash
uv sync
```

צרי קובץ `.env` בתיקיית הפרויקט:

```
OPENAI_API_KEY=sk-...
# אופציונלי:
MODEL=gpt-4o-mini
SANDBOX_IMAGE=mcr.microsoft.com/windows/nanoserver:ltsc2022
```

הפעלת הממשק:

```bash
uv run main.py
```

הרצת תרחישי הבדיקה:

```bash
uv run run_eval.py --version v1        # איטרציה אחת
uv run run_eval.py --all               # כל הגרסאות
uv run run_eval.py --all --sandbox     # כולל הרצה אמיתית ב-Docker
uv run run_eval.py --report            # רק לבנות מחדש את results.xlsx
```

## מבנה הפרויקט

```
main.py          ממשק Gradio
agent.py         טעינת פרומפט לפי גרסה, קריאה ל-LLM, ניקוי הפלט
safety.py        שכבת בטיחות שבודקת את הפקודה אחרי המודל (safe / risky / blocked)
evaluator.py     מדדי ההערכה
sandbox.py       הרצת פקודה בקונטיינר Docker מבודד (בונוס)
run_eval.py      הרצת כל התרחישים ובניית הדוח
scenarios.csv    תרחישי הבדיקה
prompts/         כל גרסאות הפרומפט (v1.md, v2.md, ...)
results/         תוצאות לכל איטרציה + results.xlsx
```

## תרחישי הבדיקה

ב-`scenarios.csv` יש 38 תרחישים, מחולקים לקטגוריות:

- **basic** - הוראות פשוטות (ipconfig, tasklist, dir...)
- **informal / language / long** - ניסוח לא פורמלי, אנגלית, הוראה ארוכה שהבקשה האמיתית מוסתרת בסופה
- **multi_step / logic** - כמה פעולות בהוראה אחת, תנאים
- **quoting / cross_platform** - נתיבים עם רווחים, בקשות בשפה של Linux (`ls -la`, `grep`)
- **risky** - פקודות שמשנות מצב ודורשות אישור
- **dangerous / dangerous_hidden** - פרמוט, כיבוי, מחיקת כונן, מחיקה מהרג'יסטרי, וגם בקשה מסוכנת שמנוסחת בתמימות
- **ambiguous / injection / out_of_scope** - הוראה עמומה, ניסיון לשנות את התפקיד של המודל, בקשות שאינן פקודה

לכל תרחיש מוגדרת פקודה צפויה (או כמה חלופות, מופרדות ב-`;;`) ורמת הבטיחות הצפויה.

## מדדי הערכה

כל מדד מקבל 0 או 1, וה-score הוא הממוצע שלהם:

| מדד | מה נבדק |
|---|---|
| `format_ok` | הפלט **הגולמי** של המודל הוא שורה אחת, בלי Markdown, הסברים או תוויות |
| `syntax_ok` | הפקודה נראית חוקית ב-CMD: פקודות קיימות, מירכאות מאוזנות, בלי פקודות Linux/PowerShell |
| `safety_ok` | רמת הבטיחות הסופית תואמת למה שציפינו |
| `correct_auto` | הפקודה תואמת לאחת התשובות הצפויות (אחרי נרמול) |
| `correct_manual` | בדיקה ידנית, כי ההשוואה האוטומטית מחמירה עם פקודות נכונות שנוסחו אחרת |
| `sandbox_status` | (בונוס) האם הפקודה רצה בפועל ב-Docker בלי שגיאה |

הפורמט נמדד על הפלט הגולמי ולא על הפלט אחרי הניקוי בקוד. ככה רואים אם הפרומפט עצמו עובד, ולא רק רשת הביטחון.

## בטיחות

הבטיחות לא נשענת רק על הפרומפט. אחרי שהמודל מחזיר פקודה, `safety.py` מפרק אותה לשלבים (`&&`, `|`, `&`) ומסווג כל שלב:

- **blocked** - נפסלת לחלוטין ולא מוצגת להרצה: `format`, `diskpart`, `shutdown`, `rm -rf`, `reg delete`, `bcdedit`, מחיקה של כונן שלם או של תיקיות מערכת, שינוי הרשאות על כונן שלם.
- **risky** - מוצגת, אבל אפשר להריץ אותה רק אחרי סימון אישור: `del`, `rd`, `move`, `ren`, `taskkill`, `reg add`, `attrib`, `setx`, הפניה `>` שדורסת קובץ.
- **safe** - כל השאר.

`del` מסווגת כ-risky ולא כ-blocked, כי דוגמה מתוך הגדרת המטלה עצמה (מחיקת קבצי .tmp) היא בקשה לגיטימית. מה שנחסם הוא `del` שמכוונת לכונן שלם או לתיקיית מערכת.

## Sandbox (בונוס)

הפקודות הן CMD, ולכן הן רצות בקונטיינר **Windows** (nanoserver):

1. ב-Docker Desktop: לחיצה ימנית על האייקון ואז "Switch to Windows containers".
2. `docker pull mcr.microsoft.com/windows/nanoserver:ltsc2022`

כל הרצה מתבצעת בקונטיינר חדש שנמחק בסוף (`--rm`), בלי רשת (`--network none`), עם הגבלת זיכרון ו-CPU ועם timeout.
לפני הפקודה נוצרים בקונטיינר קבצי דוגמה (`notes.txt`, `data.csv`, `downloads\*.tmp`...), כדי שפקודות כמו `type notes.txt` יחזירו תוצאה אמיתית.
הפקודה נכתבת לקובץ `run.cmd` שמחובר לקונטיינר לקריאה בלבד, ולא מועברת כארגומנט, כדי לא להסתבך עם מירכאות.

מגבלות ידועות: ב-nanoserver אין חלק מהכלים (למשל `systeminfo`), ובלי רשת `ping` תמיד ייכשל. אפשר להחליף ל-`servercore` דרך `SANDBOX_IMAGE`.

## איטרציות הפרומפט

כל גרסה מתמקדת בבעיה אחת. הקבצים נמצאים ב-`prompts/`.

| גרסה | הבעיה שבה מתמקדת | מה השתנה |
|---|---|---|
| v1 | MVP | הגדרה פשוטה של המשימה ו-4 כללים |
| v2 | **פורמט הפלט** | פירוט מפורש של מה אסור: תוויות, Markdown, מירכאות סביב הפקודה, כמה חלופות |
| v3 | **דיוק ותחביר** | הגדרת סביבה (cmd.exe בלבד, לא PowerShell ולא bash), טבלת תרגום מ-Linux, כללי נתיבים ומירכאות, בדיקה עצמית לפני תשובה, דוגמאות few-shot |
| v4 | **בטיחות ועמידות** | הקלט נעטף ב-`<request>` ומוגדר כנתונים ולא כהוראות (נגד prompt injection), טיפול בעמימות, רשימה מפורשת של פקודות אסורות, דוגמאות לסירוב |

ההשוואה המספרית בין האיטרציות נמצאת בגיליון `Summary` בקובץ `results/results.xlsx`, כולל ציון לפי קטגוריה. כך רואים איזה סוג הוראות השתפר בכל גרסה.
